# JichoBot

JichoBot is a desktop companion for coding agents, with an iPhone companion and an Android companion. Kito, its small slate-and-coral mascot, reflects agent activity and brings approval requests to the desktop island.

The imported codebase includes native macOS and iPhone apps, a Windows and Linux desktop app, an Android app, and an optional push relay. The intended feature set follows the imported source. See [STATUS.md](STATUS.md) for what has actually been built and exercised on this machine.

## Included behavior

The source includes agent activity and permission cards, session and tool status, question prompts, desktop pairing, agent integrations, local history and recaps, voice and dictation features, wardrobe states, update notices, iPhone activities and widgets, Android pairing and remote approvals, and an optional relay for push delivery. Integration availability depends on the agent, OS permissions, signing, and service credentials.

## Build and development

Requirements vary by platform. Use the platform README and the upstream build notes in `CLAUDE.md` as implementation guidance; Jicho-specific verification is recorded in `STATUS.md`.

```sh
# Windows/Linux desktop frontend and unit tests
cd windows
npm install
npm test

# Linux desktop app (requires Rust, Tauri system libraries, and a display)
npm run tauri dev

# Android (requires Android Studio or a configured Android SDK)
cd android
./gradlew assembleDebug

# Optional relay (requires Node.js)
cd relay
npm install
npm run typecheck
```

On macOS, generate the Xcode project from `JichoBot/project.yml` with XcodeGen, then build the `JichoBot` scheme. Signing, CloudKit, APNs, and release setup require the values listed in `STATUS.md`.

## Safety and privacy

- Credentials belong in the operating system keystore or Keychain. Never commit keys, relay secrets, signing files, or passwords.
- JichoBot has no telemetry. Do not add analytics or background reporting.
- Hook relays must exit promptly when the app is unavailable and must never hold an agent indefinitely.
- Never write an agent configuration without a backup and a reviewable diff. Ask for a user click before approving a permission or sending mail.
