# JICHO / Coucou architecture comparison

**Source inspected:** Coucou `main` at `0d7fe58` (2026-11-13), cloned to `/tmp/jicho-coucou` for this audit. Generated outputs and binary assets were excluded. The JICHO column reflects the 2026-11-17 working tree; verification details are in [`COMPLETION_LEDGER.md`](COMPLETION_LEDGER.md).

| Area | Coucou source pattern | JICHO today | JICHO decision |
| --- | --- | --- | --- |
| macOS island | SwiftUI/AppKit `NSPanel` with borderless, non-activating behavior; a dedicated island state machine; notch-aware screen geometry and saved placement (`NotchBuddy/Sources/App/IslandWindowController.swift`, `IslandStateMachine.swift`, `IslandPlacement.swift`). | Electron compact/expanded mascot island with top-edge placement and manual offsets; native notch integration is not implemented. | Keep the app operational while planning a native Swift/AppKit parity migration. Do not claim notch integration from Electron. |
| Windows/Linux shell | Tauri 2, Rust and TypeScript (`windows/src-tauri`, `windows/src`); Linux packaging includes layer-shell support and a fallback path. | Electron only; Linux AppImage/deb builds exist, but X11/Wayland geometry and focus are unverified. | Preserve Electron until a Rust/Tauri shell proves approval, credential and installer parity. Native Linux compositor behavior remains a separate verification task. |
| Agent event relay | `docs/AGENTS.md` documents a common event vocabulary, an agent tag, and local Unix socket / Windows named-pipe ingress. Agent-specific hook/plugin payloads retain a source identity and are normalized in the relay. | Protocol v1 and Claude/Cursor/Codex CLI adapters normalize provenance through authenticated loopback HTTP with HMAC, freshness, session binding and durable nonce checks. No Unix socket or named pipe exists. Cursor and Codex live sessions are unverified. | Keep the authenticated boundary. Consider OS-local IPC only with peer/credential authentication and parity tests; a socket by itself is not authentication. |
| Island state/activity | Explicit compact/expanded state transitions, event-driven agent pills, and observed tool/ticker steps. | The mascot island is the primary activity surface and displays observed event steps, paths, current tool and evidence-based reminders. The command centre remains for history/approvals. | Render source events plainly when evidence cannot support a richer task summary. Do not invent progress or diffs. |
| Approvals | Agent-specific blocking behavior varies; Coucou documents limits per adapter. Third-party events can be display-only. | One durable SQLite-backed core holds exact Claude and Codex CLI request responses. Claude allow/deny is live-verified; Codex's Bash/`apply_patch` hook path is implemented but live-unverified. | Keep one approval authority. Adapters declare blocking and response capabilities independently; unsupported hooks stay observation-only. |
| Local IPC | Unix socket on macOS/Linux and named pipe on Windows; relay transports event envelopes to the app. | Authenticated loopback HTTP with HMAC and SQLite replay protection. | Add OS-local IPC only with peer/credential authentication and parity tests. |
| Android pairing | `docs/ANDROID_LINK.md`: explicit QR/deep-link pairing, TLS certificate pinning, device token, request fingerprint, short expiry, biometric/screen-lock check before Allow, revocation. | ntfy can publish generic alerts only; it has no decision buttons/reply channel. No JICHO mobile app or secure paired-device protocol. | Adopt the security properties, not the wire protocol. JICHO still needs a separately reviewed protocol, device identity, revocation and real-device tests. |
| Away-from-home link | `docs/RELAY_LINK.md`: direct LAN remains primary; optional opaque relay carries end-to-end encrypted frames with a separate relay access key. | No first-party relay or mobile app. | Treat as a future separately deployable component. Never use a public topic as device authentication. |
| iOS sync | iPhone uses Apple-native CloudKit/APNs synchronization and Live Activities/widgets (`NotchBuddy/Sources/Phone`, `docs/IPHONE.md`); this differs from Android's direct LAN link. | No native iOS client. | Reuse the separation of transport, identity and UI responsibilities, not Coucou's service or branding. JICHO's iOS transport remains unimplemented. |
| Tests and release | Broad Swift tests, Windows/Rust tests, Android tests, and platform-specific build/release workflows. | 30 local harness groups; Claude Code 2.1.325 real allow/deny smoke. Codex smoke timed out before a session; Cursor, Windows/macOS and mobile are unverified. | Preserve the existing foundation tests and add tests for each implemented contract. macOS, Windows and mobile claims require their own build/runtime evidence. |

## Migration plan

1. Keep `Core` and SQLite as the only local approval authority. Preserve the existing Claude command-hook response path.
2. The canonical event envelope, adapter capability contract and authenticated Claude/Cursor/Codex CLI hook relays are implemented; finish real-session verification for Cursor and Codex.
3. The island and evidence-backed reminders are implemented in Electron; finish visual, focus, display, and compositor verification.
4. Migrate to Swift/AppKit on macOS and Tauri/Rust/TypeScript on Windows/Linux only after behavioral and security parity.
5. Design JICHO-specific device identity, LAN/relay transport, and native mobile clients. Do not reuse ntfy topics or claim phone approval support until the full pairing-to-agent round trip is verified.
